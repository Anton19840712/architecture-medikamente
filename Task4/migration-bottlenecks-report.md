# Узкие места при миграции и рекомендации

## Итог по анализу

Наиболее опасные bottlenecks для "Медикаменте" связаны не только с техникой, но и с процессами:

- файловый режим `1С` и Excel-процессы;
- единый локальный сервер как инфраструктурная точка отказа;
- отсутствие чётких контрактов данных между будущими сервисами;
- дефицит наблюдаемости и аудита;
- ограниченная ёмкость текущей ИТ-команды для одновременной миграции и поддержки бизнеса.

## Категории причин

| Категория | Возможные проблемы |
|---|---|
| Инфраструктура | локальный сервер, ограниченные ресурсы, отсутствие отказоустойчивости, слабая сегментация |
| ПО и архитектура | Excel как источник правды, файловый режим `1С`, tight coupling, отсутствие API-first |
| Данные и интеграции | дублирование, низкое качество данных, нет lineage, трудно синхронизировать старую и новую модели |
| Процессы | ручной ввод, двойной учёт, отсутствие формального cutover и rollback |
| Персонал | маленькая ИТ-команда, зависимость от нескольких людей, нехватка экспертизы по security/data platform |
| Безопасность и наблюдаемость | нет SIEM/DLP, нет полного аудита, слабая видимость инцидентов |

## Рекомендации

| Мера | Что даёт | Приоритет |
|---|---|---|
| Ввести каноническую модель данных и каталог метаданных | снижает хаос интеграций и риски миграции | P1 |
| Перенести запись/CRM в новый сервис раньше других блоков | уменьшает зависимость от Excel | P1 |
| Запустить централизованный аудит и мониторинг до активного cutover | снижает MTTR и риск незаметных ошибок | P1 |
| Настроить репликацию/событийный обмен со старыми системами | даёт основу для parallel run | P1 |
| Выделить отдельный privacy/security backlog | не даёт потерять требования 152-ФЗ в миграции | P1 |
| Усилить команду ролями data engineer / security engineer / backend engineer | снимает кадровый bottleneck | P2 |
| Перевести интеграции на API gateway и очереди | повышает устойчивость | P2 |
| Постепенно выводить файловое хранение медданных из эксплуатации | снижает surface area утечки | P2 |

## Как читать диаграмму Исикавы

Центральная "проблема" диаграммы: `Снижение производительности и надёжности при миграции`.

Каждая крупная кость показывает отдельный класс причин. Для ревью важно, что причины рассматриваются одновременно с точки зрения:

- системы;
- данных;
- команды;
- операционных процессов;
- безопасности.
