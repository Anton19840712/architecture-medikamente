# Классификация данных и стратегия защиты

## 1. Классификация данных

| Класс данных | Примеры | Состояние | Чувствительность | Профиль риска |
|---|---|---|---|---|
| PII | ФИО, телефон, e-mail | at rest / transit / in use | Высокая | Утечка, мошенничество, нарушение 152-ФЗ |
| PHI | анализы, диагнозы, назначения | at rest / transit / in use | Критическая | Медицинская тайна, репутационный ущерб |
| FINANCE | чеки, платежи, возвраты | at rest / transit / in use | Высокая | Финансовое мошенничество, ошибки учёта |
| CONSENT/LEGAL | договоры, согласия | at rest / transit | Высокая | Юридические риски, споры |
| HR_CONFIDENTIAL | зарплаты, кадровые данные | at rest / transit / in use | Высокая | Утечка ПДн сотрудников |
| AUDIT | события доступа, действия пользователей | at rest / transit | Средняя/высокая | Подмена следов, потеря доказательной базы |
| ANALYTICS_RESTRICTED | обезличенные, но чувствительные наборы | at rest / transit / in use | Средняя | Реидентификация, лишний доступ |

## 2. Обоснование необходимости защиты и инструменты

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| PII | идентификация человека, риск компрометации аккаунтов и мошенничества | AES-256 at rest, TLS 1.2+, masking в UI и логах, RBAC/ABAC |
| PHI | медицинская тайна и специальные категории ПДн | AES-256/TDE, column-level encryption, MFA, ABAC, immutable audit |
| FINANCE | целостность расчётов и снижение риска финансовых нарушений | tokenization, TLS/mTLS, HSM/KMS, журналы сверки |
| CONSENT/LEGAL | юридическая доказательность и контроль сроков хранения | WORM storage для аудита, электронная подпись, encryption at rest |
| HR_CONFIDENTIAL | защита данных сотрудников и payroll | выделенный контур, RBAC, encryption at rest/in transit |
| AUDIT | нельзя допустить удаление или подмену следов доступа | append-only storage, SIEM, ограниченный доступ, резервирование |
| ANALYTICS_RESTRICTED | предотвращение реидентификации в BI/ML | pseudonymization, masking, sandbox access, query auditing |

## 3. Базовые инструменты защиты по состояниям данных

### Data at Rest

- шифрование БД (`TDE`, `AES-256`);
- шифрование томов и резервных копий;
- отдельные ключи для клинического, финансового и аналитического контуров;
- секреты и ключи в `Vault/KMS`;
- политика удаления и архивирования по тегам.

### Data in Transit

- `TLS 1.2+` между клиентами и системой;
- `mTLS` между внутренними сервисами и интеграциями;
- VPN/защищённый канал для администрирования;
- подпись и проверка схем для внешних API;
- запрет небезопасных протоколов и открытых файловых обменов.

### Data in Use

- RBAC/ABAC;
- MFA для сотрудников и администраторов;
- маскирование чувствительных полей в интерфейсах;
- изоляция сред для BI/ML;
- контроль выгрузок, clipboard/file exfiltration, DLP.

## 4. Автоматизированный контроль

| Контроль | Что отслеживает | Рекомендованное средство |
|---|---|---|
| DLP | выгрузки и пересылку чувствительных данных | InfoWatch / SearchInform / Microsoft Purview |
| SIEM | аномалии доступа и инциденты | Splunk / QRadar / ELK + Wazuh |
| UEBA | нетипичное поведение пользователей | встроенный модуль SIEM / отдельный UEBA |
| Data discovery | поиск PII/PHI в новых наборах | Apache Atlas + scanners / Purview |
| Secret scanning | утечку ключей и секретов | Vault policies + CI secret scanning |
| Backup control | шифрование и доступ к копиям | backup platform + KMS |

## 5. Привязка к требованиям 152-ФЗ

| Класс данных | Статья 152-ФЗ | Требование | Применяемые меры защиты |
|---|---|---|---|
| PHI (медицинские данные) | Ст. 10 | Специальные категории ПДн, требуют явного письменного согласия и повышенной защиты | AES-256/TDE, отдельный клинический контур, ABAC по роли + специальности + визиту, immutable audit |
| PII (идентификационные данные) | Ст. 6, 9, 14 | Обработка только при наличии согласия; субъект вправе получить доступ к своим данным | TLS 1.2+, RBAC, masking в UI/логах, consent-проверка при каждой обработке |
| CONSENT / LEGAL | Ст. 9, 17, 21 | Согласие должно быть отзываемым; ПДн удаляются по достижении целей или по запросу | WORM-хранилище для неизменяемости, Consent Service с поддержкой отзыва и удаления |
| FINANCE | Ст. 19 | Технические меры по обеспечению конфиденциальности при обработке и передаче | Tokenization, mTLS, HSM/KMS, audit reconciliation |
| HR_CONFIDENTIAL | Ст. 6, 19 | ПДн сотрудников — обработка в рамках трудового договора, защита от несанкционированного доступа | Выделенный HR-контур, RBAC, encryption at rest, ограниченный экспорт |
| AUDIT | Ст. 18.1, 19 | Организационные меры: ведение журналов, контроль действий операторов | Append-only storage, ограниченный доступ к журналам, SIEM, ротация и резервирование |

**Ключевые требования ст. 19 (технические меры):**
- использование средств защиты информации, прошедших оценку соответствия (ФСТЭК / ФСБ) для операторов ПДн в РФ;
- необходимо рассмотреть сертифицированные СКЗИ для шифрования специальных категорий ПДн (ГОСТ 28147-89 / ГОСТ Р 34.12-2015) при требовании ФСБ;
- при обработке в государственных ИС — дополнительные требования приказов ФСТЭК №17 и №21.
