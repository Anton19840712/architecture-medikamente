# Анализ соответствия 152-ФЗ (As-Is)

## Контекст

Федеральный закон «О персональных данных» (152-ФЗ) обязывает операторов ПДн обеспечить конфиденциальность, целостность и доступность данных граждан РФ. Медицинские данные относятся к **специальным категориям ПДн** (ст. 10), требующим усиленных мер защиты и явного письменного согласия субъекта.

---

## Нарушения As-Is по статьям 152-ФЗ

| Статья 152-ФЗ | Что требует | Нарушение в текущем состоянии |
|---|---|---|
| **Ст. 6** — законность обработки | ПДн обрабатываются только при наличии согласия или иного законного основания | Согласия хранятся в виде бумажных сканов без системного учёта; невозможно подтвердить наличие актуального согласия для каждого субъекта |
| **Ст. 9** — согласие субъекта | Согласие должно быть конкретным, информированным и отзываемым | Нет механизма отзыва согласия; не реализована процедура прекращения обработки по запросу клиента |
| **Ст. 10** — специальные категории ПДн | Медицинские данные (диагнозы, анализы, назначения) требуют явного письменного согласия и особых мер защиты | Медданные хранятся в JPG/PDF/Excel на общем файловом диске без сегрегации и криптозащиты |
| **Ст. 14** — право субъекта на доступ к своим данным | Субъект вправе получить информацию об обрабатываемых его ПДн | Нет механизма предоставления пациенту структурированного доступа к своим данным |
| **Ст. 17** — право на обжалование и удаление | Субъект вправе требовать удаления его ПДн | Нет процедуры удаления ПДн по запросу; Excel-файлы и сканы не имеют жизненного цикла |
| **Ст. 18** — уведомление об изменении | При изменении целей обработки требуется уведомление | Изменения в данных пациента не отслеживаются и не документируются |
| **Ст. 18.1** — организационные меры | Оператор обязан принять внутренние документы и назначить ответственного | Нет политики ИБ, нет DPO / ответственного за обработку ПДн |
| **Ст. 19** — технические и организационные меры | Применение шифрования, разграничения доступа, антивируса, резервного копирования с контролем доступа | Шифрование данных не применяется; доступ разграничен только доменной аутентификацией без RBAC/ABAC; журналирование доступа к файлам с ПДн отсутствует |
| **Ст. 21** — обеспечение прекращения обработки | При достижении целей обработки ПДн должны быть уничтожены | Нет управления сроками хранения; данные в Excel и файлы накапливаются бессрочно |
| **Ст. 22** — уведомление Роскомнадзора | Оператор ПДн обязан уведомить РКН до начала обработки | Статус уведомления не упоминается в описании компании; при расширении в новые регионы — высокий риск нарушения |

## Приоритет устранения нарушений

| Приоритет | Статья | Мера |
|---|---|---|
| P0 (срочно) | Ст. 19 | Ввести шифрование хранилищ, RBAC/ABAC и аудит доступа |
| P0 (срочно) | Ст. 10 | Изолировать медицинские данные (PHI) в отдельный защищённый контур |
| P1 | Ст. 9 | Реализовать систему управления согласиями (Consent Service) |
| P1 | Ст. 17, 21 | Создать политику и автоматизированный процесс удаления / архивирования ПДн |
| P1 | Ст. 18.1 | Разработать политику обработки ПДн и назначить DPO |
| P2 | Ст. 14 | Предоставить пациенту личный кабинет с доступом к своим данным |
| P2 | Ст. 22 | Проверить статус уведомления РКН, при необходимости подать уведомление |
